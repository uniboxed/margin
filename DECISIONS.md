# Decisions

Ambiguous calls made while building Margin, newest milestone last. "Verified" means verified in headless Chromium tests only; nothing here has been run in Safari.

## Environment

- **Playwright/Chromium:** Chromium is preinstalled in the cloud session (`/opt/pw-browsers`, Playwright 1.63.0), so E2E tests run; nothing is downloaded. `package.json` pins `playwright@1.63.0` as the only dev dependency. Tests load it through `createRequire`, so either a local `npm install` or the global copy works.
- **E2E runner:** E2E tests use `node --test` plus the `playwright` library instead of `@playwright/test`, so there's a single runner and no second dependency.
- **Closed shadow roots in tests:** page JS and Playwright locators can't see into a closed shadow root. The tests use the DevTools protocol (`DOM.getDocument` with `pierce: true` → `Runtime.callFunctionOn`) to inspect and click inside it. Production code keeps `mode: 'closed'`.

## M1 — Skeleton

- **Background as a classic service worker** (originally a module worker; changed after M7, see below).
- **`package.json` has `"type": "module"`** so the `node --test` files can use `import`.
- **Shadow host** is a custom element `<margin-sidebar-host>` appended to `<html>` (`<body>` doesn't exist at `document_start`). Its inline styles use `!important` and `all: initial` so site CSS can't move it, and it has zero size so it never blocks clicks.
- **Toggle-sidebar command** suggests `Alt+S` (Option+S). Whether Safari honors it is a manual check.
- **Icons** are generated by `scripts/make-icons.js` (no image dependencies).

## M2 — Sidebar overlay

- **Tab snapshot in storage.** Content scripts have no `tabs` API, so the background mirrors open tabs into `storage.local.tabs` (`{id, windowId, index, title, url, favIconUrl, active, lastActive}`) and the sidebar renders from storage alone. This is an addition to the SPEC data model. `onUpdated` only writes on title/url/favicon changes or load complete, not on every status tick.
- **Serialized mutations.** All background writes go through one promise queue (`mutate`) with an in-memory cache that's rebuilt from storage whenever the worker wakes, and only changed keys are written. Content scripts never write storage; they message the background.
- **Fresh-session detection.** After a browser restart, tab and window ids are reused with different meanings. If `storage.session` exists (it's cleared on restart), an empty one means "fresh: rebuild `tabSpace` from pins by URL." Otherwise `runtime.onStartup` triggers the rebuild. On a plain worker wake, assignments are kept and only reconciled.
- **Pins are URL-based** (normalized: no fragment, no bare trailing slash). A tab whose URL matches a pin in its space shows as that pin, not in the tab list. Navigating a pinned tab elsewhere turns it back into a normal tab. Arc keeps the tab↔pin link, but SPEC chose URL pins.
- **Messages:** the SPEC set plus `hello` (returns the sender's tab/window id), `openPin`, `updateSettings`, and (later) `deleteSpace`, `restoreArchive`. Handlers reply via `sendResponse` + `return true`, which both Chrome and Safari support.
- **CSS in the shadow root** is fetched from the web-accessible `content/sidebar.css` and applied as a constructable stylesheet, which is exempt from the page's CSP. A `<style>` element is the fallback. The new-tab page links the same file.
- **Hover logic** is one capture-phase `mousemove` listener on `document`: x ≤ 6px opens, x > 260px starts the 300ms hide timer, moving back inside cancels it. There's no edge hit-zone element, so the page's own left 6px stays clickable.
- **Shortcut toggle** opens the sidebar until toggled again, Esc, or a click on the page. "Keep open" in the footer sets the global `sidebarPinnedOpen`.
- **Theme:** the page's computed `color-scheme` (if `dark`), else the luminance of the body/html background, else the OS `prefers-color-scheme`.
- **"+ New tab"** calls `tabs.create` without a URL, so the browser's new-tab setting (Margin) decides the page.
- **Host debug attribute:** the host carries `data-open="true|false"` so state is visible in Web Inspector. It reveals nothing beyond the sidebar being open.

## M3 — New-tab page

- **Launcher navigates the new-tab tab itself** (`tabs.update`) instead of opening another tab.
- **URL vs. search** (`shared/search.js`, unit tested): explicit schemes pass through, `localhost`/IPs get `http://`, `name.tld[/…]` without spaces gets `https://`, and everything else is searched. `node.js` alone counts as a URL, like most browsers.
- **Search engine setting** is a URL template with `%s` (`settings.searchEngine`). The new-tab "Settings" disclosure offers DuckDuckGo (default), Google, Bing, Ecosia, and Startpage. A stored template that's not in the list shows as "Custom."
- **Pin tiles** focus an open tab with that URL, otherwise navigate the new-tab tab to it.
- **No palette auto-open on the new tab.** SPEC's layout comment mentions it, but the launcher field already does that job. The palette is available on the new tab through its shortcut (M5).

## M4 — Spaces and pins

- **Editing spaces:** right-click (or double-click) a space chip opens an inline editor in the sidebar with name, emoji, an 8-color palette, Save/Cancel, and Delete. "+" creates a space, switches this window to it, and opens the editor. The emoji is free text (paste or use the macOS emoji picker, Ctrl+⌘+Space).
- **Delete** takes two clicks ("Delete" → "Really delete?") instead of a `confirm()` dialog, which would block the page. The last space can't be deleted. Its tabs, pins, archive entries, and windows move to the first remaining space, and pins whose URL is already pinned there collapse into one.
- **Drag and drop** uses HTML5 DnD from a tab row onto a chip. The tab id is tracked in memory as well as in `dataTransfer`, because some browsers hide custom types during `dragover`.
- **Auto-hide is suspended** while the editor is open or a drag is in progress.
- **Our keystrokes stay in the sidebar:** key events stop propagating at the sidebar root, so typing a space name doesn't trigger the site's own shortcuts (e.g. GitHub's `/` or `s`). Page listeners in the capture phase still see them; that can't be prevented from a content script.
- **Archive helpers** (`archiveTab`, cap 200, one entry per URL, newest first) landed here so the cap is unit tested with the rest of the model. M6 uses them.

## M5 — Command palette

- **Default shortcut stays Option+K (`Alt+KeyK`), unverified.** I can't check whether Safari or macOS swallows it. Matching uses `KeyboardEvent.code`, so Option+K is recognized even though macOS types `˚`, and the physical key works on any keyboard layout. If it's swallowed in Safari, change it in new tab → Settings (any modifier + letter/digit/punctuation), then update the default in `state/model.js` and record it here. Manual check in TESTING.md.
- **Two triggers, de-duplicated:** a capture-phase `keydown` listener in the content script (and on the new-tab page), plus a `commands` entry `open-palette` (suggested Alt+K). The background forwards the command to the tab's content script, or as a runtime message to our new-tab page. Toggles within 200ms collapse, so both firing for one press doesn't open and immediately close it.
- **The shortcut works inside text fields too.** It's intercepted everywhere, which means a user can't type `˚` with the default key on websites. Changing the shortcut avoids that.
- **Ranking** (`shared/search.js`, unit tested): every space-separated token must fuzzy-match the title or URL. Substrings beat subsequences, prefixes and word starts get bonuses, and current-space tabs get the biggest boost, then current-space pins, actions, other-space tabs and pins, then archive. With an empty query: current-space tabs by recency, then actions; the archive is hidden until you type. The current tab isn't suggested.
- **"Open URL / Search for …"** comes first when the text is a URL and last when it's a search, so Enter on a fuzzy match isn't hijacked. From a web page it opens a new tab (Arc's ⌘T behavior); on the new-tab page it navigates in place.
- **Actions:** New tab, Pin current tab (only on unpinned web pages), Toggle sidebar (not on the new-tab page, where it's always open), and one "Switch to space …" per other space.
- **`content/palette.css`** was added next to `sidebar.css` (not in SPEC's layout) so each shadow root only loads its own styles.
- **Keys:** ↑/↓ (or Ctrl+N/Ctrl+P) wrap around, Enter runs, Esc or a click on the backdrop closes, and focus returns to where it was.

## M6 — Auto-archive

- **Both schedulers are implemented; which one runs depends on the browser.** If `browser.alarms` exists, a 15-minute alarm (`margin-archive`) runs the check (verified in Chromium). Otherwise the check runs on tab activation, throttled to once every 5 minutes. Either way, it also runs every time the background wakes. The background logs which path it took (`[margin] auto-archive via …`). Which one Safari uses is a manual check. `alarms` was added to `permissions`.
- **Staleness clock:** `tabs[id].lastActive`, stamped when a tab gains or loses focus. Safari's `tab.lastAccessed` is used only as a seed when present. When a tab is first seen with no history, the clock starts then, so a restart never archives everything at once. On a fresh browser session all clocks restart.
- **Never auto-archived:** the active tab of each window, tabs pinned in their own space (a pin in another space doesn't protect it), and non-web pages (our new tab, `about:`, Safari internal pages).
- **`archiveAfterHours: 0` disables auto-archive.** It's editable on the new tab under Settings.
- **Closing a tab from Margin's × archives it**, like Arc. Tabs closed with ⌘W or by closing a window are **not** archived, deliberately: `tabs.onRemoved` can't tell a deliberate close from a window close or quit, and archiving every one of those would flood the archive.
- **Restore** removes the entry, reopens the URL in its original space, and switches the window to that space so the tab is visible. That space falls back to the first space if it was deleted. From the new tab it navigates in place; from the palette it opens a new tab.
- **Debug hook:** `margin.archiveNow()` in the background's console (Web Inspector) runs the check immediately. E2E uses it with a 1-second threshold.

## Safari behavior fallbacks (SPEC "design defensively")

| # | Assumption | Fallback in code |
|---|------------|------------------|
| 1 | `chrome_url_overrides.newtab` works | Nothing depends on the new-tab page. The overlay sidebar, palette ("Open URL / Search"), and archive restore all work from any website |
| 2 | `tab.favIconUrl` is populated | `<img>` only for `http(s)`/`data:` icons, swapped for a colored letter avatar on error or when missing. No favicon services |
| 3 | `commands` shortcuts work | Content-script `keydown` listener as the primary path, `commands` as a backup, de-duplicated. The shortcut is user-configurable |
| 4 | `browser.alarms` exists | Feature-detected. Without it, the check runs on wake and on (throttled) tab activation |
| 5 | The background wakes on `sendMessage` and may unload anytime | All state is in `storage.local` and re-read on wake. Content scripts render from storage without the background, and retry a message once after 250ms if it fails or returns nothing |

## M7 — Polish and docs

- **"Clean build" = `tests/manifest.test.js`:** there's no bundler, so the build check confirms the manifest still meets SPEC's constraints, that every file referenced by the manifest and `newtab.html` exists, that every script parses, and that the extension code contains no third-party URLs (search-engine templates are allowed).
- **Message retry:** content-script messages retry once after 250ms (Safari check #5).

## Status

M1–M7 complete. Unit tests (`npm test`) and Chromium E2E tests (`npm run test:e2e`) pass. Nothing has been run in Safari: TESTING.md lists the manual checks, starting with the five Safari behaviors.

## Post-M7 — Classic background worker

- **Confirmed on Tirth's Mac:** `safari-web-extension-converter` warned that the manifest key `type` (`"background": {"type": "module"}`) isn't supported by his Safari. Safari would then load `background.js` as a classic worker, and its `import` line would be a syntax error, so the background would never start.
- **Fix:** `state/model.js` is now a classic script like the `shared/` files, attaching `globalThis.Margin.model`. `background.js` loads it with `importScripts('state/model.js')`, and `"type"` is gone from the manifest. Unit tests import it for the side effect and read `globalThis.Margin.model`. `tests/manifest.test.js` asserts `background.type` stays unset.
- **Bundle IDs:** the converter gave the app `io.tirth.Margin` and the extension `io.tirth.margin.Extension`, and Xcode rejected the extension ID as not prefixed by the app's. `scripts/make-xcode.sh` regenerates `xcode/` and patches the app to `io.tirth.margin`, the extension to `io.tirth.margin.Extension`, and the Swift `extensionBundleIdentifier` to match.

## Safari results (Tirth's Mac, 2026-10-24)

- Checks 1, 3, 4, 5, A and B pass. Details are in TESTING.md. Option+K stays the default palette shortcut. `browser.alarms` drives auto-archive.
- **Favicons:** Safari shows letter avatars. It's still open whether `tab.favIconUrl` is empty. If it is, letters stay: SPEC rules out favicon services, and fetching `https://<host>/favicon.ico` from inside other sites' pages would be a cross-site request.
- **Toggle with "Keep open":** the toggle shortcut used to do nothing while `sidebarPinnedOpen` was on. It now turns "Keep open" off and hides the sidebar.
- **Overlay hides content while kept open:** confirmed as designed (SPEC hard constraint). Pushing the page wouldn't move `position: fixed` headers and breaks sticky/fixed layouts.
