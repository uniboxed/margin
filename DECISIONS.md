# Decisions

Ambiguous calls made while building Margin, newest milestone last. "Verified" means verified in headless Chromium tests only; nothing here has been run in Safari.

## Environment

- **Playwright/Chromium:** Chromium is preinstalled in the cloud session (`/opt/pw-browsers`, Playwright 1.63.0), so E2E tests run; nothing is downloaded. `package.json` pins `playwright@1.63.0` as the only dev dependency. Tests load it through `createRequire`, so either a local `npm install` or the global copy works.
- **E2E runner:** E2E tests use `node --test` plus the `playwright` library instead of `@playwright/test`, so there's a single runner and no second dependency.
- **Closed shadow roots in tests:** page JS and Playwright locators can't see into a closed shadow root. The tests use the DevTools protocol (`DOM.getDocument` with `pierce: true` → `Runtime.callFunctionOn`) to inspect and click inside it. Production code keeps `mode: 'closed'`.

## M1 — Skeleton

- **Background as a classic service worker** (originally a module worker; changed after M7, see below).
- **`package.json` has `"type": "module"`** so the `node --test` files can use `import`.
- **Shadow host** is a custom element `<margin-sidebar-host>` appended to `<html>` (`<body>` doesn't exist at `document_start`). Its inline styles use `!important` and `all: initial` so site CSS can't move it, and it has zero size so it never blocks clicks.
- **Toggle-sidebar command** suggests `Alt+S` (Option+S). Whether Safari honors it is a manual check.
- **Icons** are generated by `scripts/make-icons.js` (no image dependencies).

## M2 — Sidebar overlay

- **Tab snapshot in storage.** Content scripts have no `tabs` API, so the background mirrors open tabs into `storage.local.tabs` (`{id, windowId, index, title, url, favIconUrl, active, lastActive}`) and the sidebar renders from storage alone. This is an addition to the SPEC data model. `onUpdated` only writes on title/url/favicon changes or load complete, not on every status tick.
- **Serialized mutations.** All background writes go through one promise queue (`mutate`) with an in-memory cache that's rebuilt from storage whenever the worker wakes, and only changed keys are written. Content scripts never write storage; they message the background.
- **Fresh-session detection.** After a browser restart, tab and window ids are reused with different meanings. If `storage.session` exists (it's cleared on restart), an empty one means "fresh: rebuild `tabSpace` from pins by URL." Otherwise `runtime.onStartup` triggers the rebuild. On a plain worker wake, assignments are kept and only reconciled.
- **Pins are URL-based** (normalized: no fragment, no bare trailing slash). A tab whose URL matches a pin in its space shows as that pin, not in the tab list. Navigating a pinned tab elsewhere turns it back into a normal tab. Arc keeps the tab↔pin link, but SPEC chose URL pins.
- **Messages:** the SPEC set plus `hello` (returns the sender's tab/window id), `openPin`, `updateSettings`, and (later) `deleteSpace`, `restoreArchive`. Handlers reply via `sendResponse` + `return true`, which both Chrome and Safari support.
- **CSS in the shadow root** is fetched from the web-accessible `content/sidebar.css` and applied as a constructable stylesheet, which is exempt from the page's CSP. A `<style>` element is the fallback. The new-tab page links the same file.
- **Hover logic** is one capture-phase `mousemove` listener on `document`: x ≤ 6px opens, x > 260px starts the 300ms hide timer, moving back inside cancels it. There's no edge hit-zone element, so the page's own left 6px stays clickable.
- **Shortcut toggle** opens the sidebar until toggled again, Esc, or a click on the page. "Keep open" in the footer sets the global `sidebarPinnedOpen`.
- **Theme:** the page's computed `color-scheme` (if `dark`), else the luminance of the body/html background, else the OS `prefers-color-scheme`.
- **"+ New tab"** calls `tabs.create` without a URL, so the browser's new-tab setting (Margin) decides the page.
- **Host debug attribute:** the host carries `data-open="true|false"` so state is visible in Web Inspector. It reveals nothing beyond the sidebar being open.

## M3 — New-tab page

- **Launcher navigates the new-tab tab itself** (`tabs.update`) instead of opening another tab.
- **URL vs. search** (`shared/search.js`, unit tested): explicit schemes pass through, `localhost`/IPs get `http://`, `name.tld[/…]` without spaces gets `https://`, and everything else is searched. `node.js` alone counts as a URL, like most browsers.
- **Search engine setting** is a URL template with `%s` (`settings.searchEngine`). The new-tab "Settings" disclosure offers DuckDuckGo (default), Google, Bing, Ecosia, and Startpage. A stored template that's not in the list shows as "Custom."
- **Pin tiles** focus an open tab with that URL, otherwise navigate the new-tab tab to it.
- **No palette auto-open on the new tab.** SPEC's layout comment mentions it, but the launcher field already does that job. The palette is available on the new tab through its shortcut (M5).

## M4 — Spaces and pins

- **Editing spaces:** right-click (or double-click) a space chip opens an inline editor in the sidebar with name, emoji, an 8-color palette, Save/Cancel, and Delete. "+" creates a space, switches this window to it, and opens the editor. The emoji is free text (paste or use the macOS emoji picker, Ctrl+⌘+Space).
- **Delete** takes two clicks ("Delete" → "Really delete?") instead of a `confirm()` dialog, which would block the page. The last space can't be deleted. Its tabs, pins, archive entries, and windows move to the first remaining space, and pins whose URL is already pinned there collapse into one.
- **Drag and drop** uses HTML5 DnD from a tab row onto a chip. The tab id is tracked in memory as well as in `dataTransfer`, because some browsers hide custom types during `dragover`.
- **Auto-hide is suspended** while the editor is open or a drag is in progress.
- **Our keystrokes stay in the sidebar:** key events stop propagating at the sidebar root, so typing a space name doesn't trigger the site's own shortcuts (e.g. GitHub's `/` or `s`). Page listeners in the capture phase still see them; that can't be prevented from a content script.
- **Archive helpers** (`archiveTab`, cap 200, one entry per URL, newest first) landed here so the cap is unit tested with the rest of the model. M6 uses them.

## M5 — Command palette

- **Default shortcut stays Option+K (`Alt+KeyK`), unverified.** I can't check whether Safari or macOS swallows it. Matching uses `KeyboardEvent.code`, so Option+K is recognized even though macOS types `˚`, and the physical key works on any keyboard layout. If it's swallowed in Safari, change it in new tab → Settings (any modifier + letter/digit/punctuation), then update the default in `state/model.js` and record it here. Manual check in TESTING.md.
- **Two triggers, de-duplicated:** a capture-phase `keydown` listener in the content script (and on the new-tab page), plus a `commands` entry `open-palette` (suggested Alt+K). The background forwards the command to the tab's content script, or as a runtime message to our new-tab page. Toggles within 200ms collapse, so both firing for one press doesn't open and immediately close it.
- **The shortcut works inside text fields too.** It's intercepted everywhere, which means a user can't type `˚` with the default key on websites. Changing the shortcut avoids that.
- **Ranking** (`shared/search.js`, unit tested): every space-separated token must fuzzy-match the title or URL. Substrings beat subsequences, prefixes and word starts get bonuses, and current-space tabs get the biggest boost, then current-space pins, actions, other-space tabs and pins, then archive. With an empty query: current-space tabs by recency, then actions; the archive is hidden until you type. The current tab isn't suggested.
- **"Open URL / Search for …"** comes first when the text is a URL and last when it's a search, so Enter on a fuzzy match isn't hijacked. From a web page it opens a new tab (Arc's ⌘T behavior); on the new-tab page it navigates in place.
- **Actions:** New tab, Pin current tab (only on unpinned web pages), Toggle sidebar (not on the new-tab page, where it's always open), and one "Switch to space …" per other space.
- **`content/palette.css`** was added next to `sidebar.css` (not in SPEC's layout) so each shadow root only loads its own styles.
- **Keys:** ↑/↓ (or Ctrl+N/Ctrl+P) wrap around, Enter runs, Esc or a click on the backdrop closes, and focus returns to where it was.

## M6 — Auto-archive

- **Both schedulers are implemented; which one runs depends on the browser.** If `browser.alarms` exists, a 15-minute alarm (`margin-archive`) runs the check (verified in Chromium). Otherwise the check runs on tab activation, throttled to once every 5 minutes. Either way, it also runs every time the background wakes. The background logs which path it took (`[margin] auto-archive via …`). Which one Safari uses is a manual check. `alarms` was added to `permissions`.
- **Staleness clock:** `tabs[id].lastActive`, stamped when a tab gains or loses focus. Safari's `tab.lastAccessed` is used only as a seed when present. When a tab is first seen with no history, the clock starts then, so a restart never archives everything at once. On a fresh browser session all clocks restart.
- **Never auto-archived:** the active tab of each window, tabs pinned in their own space (a pin in another space doesn't protect it), and non-web pages (our new tab, `about:`, Safari internal pages).
- **`archiveAfterHours: 0` disables auto-archive.** It's editable on the new tab under Settings.
- **Closing a tab from Margin's × archives it**, like Arc. Tabs closed with ⌘W or by closing a window are **not** archived, deliberately: `tabs.onRemoved` can't tell a deliberate close from a window close or quit, and archiving every one of those would flood the archive.
- **Restore** removes the entry, reopens the URL in its original space, and switches the window to that space so the tab is visible. That space falls back to the first space if it was deleted. From the new tab it navigates in place; from the palette it opens a new tab.
- **Debug hook:** `margin.archiveNow()` in the background's console (Web Inspector) runs the check immediately. E2E uses it with a 1-second threshold.

## Safari behavior fallbacks (SPEC "design defensively")

| # | Assumption | Fallback in code |
|---|------------|------------------|
| 1 | `chrome_url_overrides.newtab` works | Nothing depends on the new-tab page. The overlay sidebar, palette ("Open URL / Search"), and archive restore all work from any website |
| 2 | `tab.favIconUrl` is populated | `<img>` only for `http(s)`/`data:` icons, swapped for a colored letter avatar on error or when missing. No favicon services |
| 3 | `commands` shortcuts work | Content-script `keydown` listener as the primary path, `commands` as a backup, de-duplicated. The shortcut is user-configurable |
| 4 | `browser.alarms` exists | Feature-detected. Without it, the check runs on wake and on (throttled) tab activation |
| 5 | The background wakes on `sendMessage` and may unload anytime | All state is in `storage.local` and re-read on wake. Content scripts render from storage without the background, and retry a message once after 250ms if it fails or returns nothing |

## M7 — Polish and docs

- **"Clean build" = `tests/manifest.test.js`:** there's no bundler, so the build check confirms the manifest still meets SPEC's constraints, that every file referenced by the manifest and `newtab.html` exists, that every script parses, and that the extension code contains no third-party URLs (search-engine templates are allowed).
- **Message retry:** content-script messages retry once after 250ms (Safari check #5).

## Post-M7 — Classic background worker

- **Confirmed on Tirth's Mac:** `safari-web-extension-converter` warned that the manifest key `type` (`"background": {"type": "module"}`) isn't supported by his Safari. Safari would then load `background.js` as a classic worker, and its `import` line would be a syntax error, so the background would never start.
- **Fix:** `state/model.js` is now a classic script like the `shared/` files, attaching `globalThis.Margin.model`. `background.js` loads it with `importScripts('state/model.js')`, and `"type"` is gone from the manifest. Unit tests import it for the side effect and read `globalThis.Margin.model`. `tests/manifest.test.js` asserts `background.type` stays unset.
- **Bundle IDs:** the converter gave the app `io.tirth.Margin` and the extension `io.tirth.margin.Extension`, and Xcode rejected the extension ID as not prefixed by the app's. `scripts/make-xcode.sh` regenerates `xcode/` and patches the app to `io.tirth.margin`, the extension to `io.tirth.margin.Extension`, and the Swift `extensionBundleIdentifier` to match.

## Arc frame, push when kept open, faster first render (2026-10-25)

- **Late sidebar fixed.** The sidebar used to wait for the background's `hello` reply before drawing, because it didn't know its window. In Safari the background is usually unloaded, so the sidebar showed up only after a wake-up, often after the page finished loading. It now draws straight from storage using `view.guessWindow()` (single window → that one; else a tab with this URL, active and most recent first) and corrects itself when `hello` answers. The panel is also hidden until its CSS is applied, so it never flashes unstyled.
- **Arc-style frame.** The sidebar is now opaque and shares one color with a frame around the page: an 8px margin top, right and bottom with 10px rounded page corners, tinted 14% toward the active space's color. The frame is a `pointer-events: none` overlay (a rounded "hole" with a huge box-shadow), so the page stays fully clickable. It shows only while the sidebar is open (Tirth's choice), and the new-tab page uses the same layout.
- **Push when kept open (Tirth's choice, overriding SPEC's original "never push").** With `sidebarPinnedOpen`, the content script adopts a stylesheet on the document: `@media screen { html { margin-left: 260px; margin-right: 8px; width: auto; overflow-x: hidden } }`. It's a constructable sheet, not page markup or an inline style. A `<style>` element is the fallback, and it isn't applied to non-HTML documents. It's removed when "Keep open" turns off, and print is unaffected. Top and bottom aren't pushed (the frame overlays 8px there), because pushing vertically adds an outer scrollbar on full-height app layouts like Gmail and Teams. Known breakage: `position: fixed` elements don't move, so left-anchored fixed headers stay partly under the sidebar; `100vw` elements are clipped on the right; viewport-centered modals sit off-center; sites keep their media queries for the full window width. Pages that replace `document.adoptedStyleSheets` wholesale would drop the push until the next state change.

## Floating hover sidebar (2026-10-25)

- **Two looks, per Tirth:** hover (auto-hide) shows a floating card: inset 8px from the window edges, 12px radius, shadow, slightly translucent with backdrop blur, no frame, and the page never moves. "Keep open" docks it flush to the window (opaque, no radius) with the frame and the push. The frame no longer appears in hover mode.
- **Reveal zone widened from 6px to 10px**, and hide now starts once the cursor passes the card's right edge (268px). Safari has its own sidebar that opens when the cursor rests at the window's left edge, and extensions can't disable it. Margin opens instantly in the wider zone, so the user doesn't need to rest at the very edge.

## Sidebar instantly on page load (2026-10-25)

- **Cause:** with "Keep open", the sidebar showed up only after the page finished loading in Safari. Waiting for the background was fixed earlier. The remaining wait was the stylesheet: the content script `fetch()`ed `content/sidebar.css` and kept the panel hidden until it arrived, and in Safari that request likely queues behind the page's own resources. On top of that, the docked sidebar slid in (160ms) on every navigation.
- **Fix:** `content/*.css` stay the source of truth. `scripts/build-styles.js` (`npm run styles`) bundles them into `content/styles.js`, which loads as a content script before the UI and is applied synchronously, so the sidebar is styled from its first frame. A unit test fails if `styles.js` is stale, and another fails if a content script `fetch`es. With no stylesheets fetched by pages, `web_accessible_resources` was removed, so web pages can no longer probe for Margin's files.
- **No animation on first render:** an `instant` class suppresses transitions until two frames after the first render, so a kept-open sidebar is simply there. Hover still animates.
- **The only remaining wait** is one `storage.local.get` (needed to know the spaces, tabs and the "Keep open" setting). Each page logs one `console.debug` line after load (debug level since 2026-10-25, so it's hidden unless the console shows Debug messages): `[margin] timing (ms) injected=… storage=… rendered=… | page DOMContentLoaded=… load=…`, all in ms since navigation start. A late `injected` means Safari ran the content script late; a late `storage` means the `storage.local` read was slow. In Chromium, `rendered` is about 20–45ms against a 1,500ms load.

## First-paint placeholder for "Keep open" (2026-10-25)

- **Measured in Safari (Tirth, google.com):** `injected=176–266 rendered=190–294 | DOMContentLoaded=511–544 load=945–1145`. Margin renders 15–30ms after Safari runs its content script, but Safari runs `document_start` content scripts about 200ms after navigation start, after fast pages have already painted. No content-script change can beat that.
- **Fix:** while `sidebarPinnedOpen` is on, the background registers `content/docked.css` with `scripting.registerContentScripts` (id `margin-docked`, `document_start`) and unregisters it when "Keep open" turns off. It re-syncs on every `settings` change and on wake. Registered CSS is applied before first paint, ahead of content scripts. It pushes `html` (same geometry as the JS push) and paints the docked sidebar and frame background with a single `html::after`: a fixed rounded "hole" with a 100vmax box-shadow, `pointer-events: none`, z-index one below Margin's host. The real sidebar and frame render on top moments later. The placeholder uses the default space tint, light or dark by `prefers-color-scheme`.
- **Switching it off per page:** if a page with the placeholder isn't docked (Keep open turned off, or the setting changed mid-load), `sidebar.js` sets `data-margin-docked="off"` on `<html>`, which the placeholder's selectors exclude. This is the only attribute Margin ever sets on a page's own elements, and only when the placeholder is present.
- **Feature-detected:** the `scripting` permission was added. Without `scripting.registerContentScripts`, the sidebar appears when the content script runs, as before. Known cost: a site with its own `html::after` loses it while docked.

## One highlighted tab per window (2026-10-25)

- **Bug (seen in Safari):** several tabs highlighted at once after opening pages in a row. Cause: `upsertTab` copied `active` from every `tabs.onUpdated` event. Safari can deliver an update for a page that finished loading after the user switched away, still saying `active: true`, which re-highlighted it. Also, a newly created focused tab didn't clear the old highlight unless Safari also sent `onActivated`.
- **Fix in the model:** for known tabs, `active` is now owned by `activateTab()` (exactly one per window), plus the `tabs.query` resync. Updates no longer change it. A new tab that arrives focused activates itself and clears the rest of its window. `activateTab` falls back to the tab's own window when the event has no `windowId`. Unit tests cover the late update, ⌘T without `onActivated`, and activation before creation.
- **Fix in the view:** `view.sidebar(state, windowId, currentTabId)` highlights the tab the sidebar is drawn in (the page being looked at is by definition active). So even a briefly stale snapshot can't highlight the wrong row on the visible page. The new tab passes its own id.

## Safari's own edge sidebar (2026-10-25)

- Safari reveals its own sidebar when the cursor rests at the left edge of a **full-screen** window. It has no setting for this, and extensions can't affect Safari's UI. Mitigations: README recommends Window → Fill instead of full screen, or Keep open. `view.revealZone()` widens Margin's reveal zone from 10px to 24px when the window covers the whole screen (`outerWidth/outerHeight >= screen`), so Margin opens before the cursor reaches the edge. In normal windows it stays 10px to avoid accidental opens near pages' left-edge controls.

## Experiment: sidebar as its own window (2026-10-25)

- **Why:** an in-page sidebar can't exist before Safari paints a new page (the blank moment on navigation), on Safari's own pages, or on PDFs. Safari has no `sidePanel` or `sidebar_action` (checked October 2026), so the only extension-only way to keep a sidebar on screen is a separate window. Tirth chose to try it as an opt-in experiment before considering a native companion app (still out of scope).
- **How:** `setDock {on}` (new tab → Settings checkbox, the palette "Dock sidebar as its own window", or "Undock" in the dock window). On, the background opens `dock/dock.html` as a `type: 'popup'` window, 260px wide, at the left edge of the last-focused normal window, and shrinks that window by 260px. `shared/dock.js` computes the geometry (unit tested). The window must be at least 740px wide. `state.dock` stores `{dockWindowId, targetWindowId, original, requested, actual}`. The dock page renders the normal sidebar for the target window, so clicks act on it. Since Safari has no window-moved event, the dock page polls the target every 500ms and re-docks (`followLayout`, 2px slack), reporting the result via `dockReport`. Off (or when either window closes) gives the target its 260px back. Turning it on also turns "Keep open" off. In the target window, the in-page sidebar and the new tab's built-in sidebar step aside. The dock page's own tab is kept out of the tab list, palette, and archive.
- **What the experiment measures:** whether Safari honors `left/top/width/height` for extension-created popup windows and for resizing a normal window, and what `type` it reports. The dock window shows "✓ Placed as asked / ✗ Not placed as asked" and "follows ✓/✗", with the exact numbers on hover. The background logs `[margin] dock …`. A refused resize is recorded (`actual.targetError`) instead of failing the dock.
- **Known limits even if Safari cooperates:** a separate window with its own title bar, up to 0.5s lag when the Safari window moves, full screen doesn't work (macOS gives each window its own Space), and one dock per profile next to one window.
- **Chromium notes:** headless Chromium validates window bounds against an 800×600 virtual display, and Playwright resizes newly opened pages to its default viewport. So E2E sets sizes after opening pages, and the dock's initial placement is corrected by the follow loop there. The E2E checks the requested layout, the popup type, following, and undocking.

### Dock experiment: first Safari result (2026-10-25)

- **From Tirth's screen recording:** Safari opens the dock as a narrow window, about 260pt, with traffic lights and a compact title bar, at the screen's left edge. The Safari window was resized to sit right of it. So **Safari does honor extension window positions and sizes**, close enough to look right. The status said "✗ Not placed as asked" because Safari's reported coordinates are offset from where it draws windows (the dock was asked for -34pt and macOS kept it at 0).
- **Bug: the dock jumped off-screen and back about twice a second.** The follow loop re-requested the absolute "ideal" position (`target.left - 260`) on every tick. With Safari's offset coordinates that position was off-screen; macOS put the window back, and the next tick moved it again. Fix: `followLayout(prev, target, dock)` now follows **relatively**. It moves the dock only when the target window itself moved or resized since the last tick, by the same delta, from the dock's real position, clamped to the screen's available area. It never re-requests a spot just because the dock isn't exactly where the math says. Unit tests cover the offset case; E2E checks the dock stays still while idle.
- **Tests:** Playwright's default viewport resized every new window, including the dock popup, to 1280×720. `launch()` now passes `viewport: null`, so tests use real window sizes, and Chromium places both windows exactly as asked.
- **Dropped (Tirth, 2026-10-25).** In Safari, the dock window visibly lagged and flickered when the Safari window was dragged: Safari gives extensions no window-moved event, so the dock can only catch up after polling. It also can't exist in full screen, where macOS gives each window its own Space. Both are inherent to a separate window, so the experiment was removed entirely (code, tests, settings switch, palette action). The in-page sidebar remains the only sidebar. The remaining way to a truly persistent sidebar is a native companion app, which is still out of scope. Leftover `dock` and `settings.dockWindow` values from the experiment in `storage.local` are ignored.

## "+" space editor race (2026-10-25)

- **Bug:** clicking "+" sometimes created the space but never opened its editor. The editor was set to open when the new space appeared in storage, but that was only set up once the `createSpace` reply arrived. When storage delivered the space first, the trigger had already passed. It showed up as intermittent E2E failures in full runs. ## Tab and space shortcuts (2026-10-25)

- **⌘⌥↓ / ⌘⌥↑:** next/previous tab in the order the sidebar shows them: open pinned tabs, then the space's tabs (`view.cycleTab`). Wraps at both ends. From a tab that isn't listed (e.g. one from another space), ↓ goes to the first and ↑ to the last. Holding the keys repeats.
- **⌘⌥→ / ⌘⌥←:** next/previous space for this window (`view.cycleSpace`), wrapping. As SPEC defines spaces, this changes only what the sidebar shows; the current page stays. In auto-hide mode the sidebar peeks open for 1.2s so the new space is visible. Hovering or toggling during the peek keeps it open. Held keys don't repeat, so you don't fly through spaces.
- **Handled** by one capture-phase `keydown` listener (`shortcuts.installNavigation`) in the content script and on the new-tab page. It calls `preventDefault` and `stopImmediatePropagation`, so sites don't get the arrow key. Like Arc, Margin takes these keys on every site, including in text fields. That shadows site shortcuts that use the same keys, e.g. multi-cursor ⌘⌥↑/↓ in web code editors. They're fixed (not a setting) for now. There's no `commands` fallback: Chrome only allows four suggested command keys, and two are already used.
- **Needs a Safari check:** whether Safari or macOS reserves any of these combos before the page sees them (same as the Option+K check).

## One sidebar color (2026-10-25)

- **Per Tirth:** the sidebar has one background color for now (a setting may come later). It's no longer tinted by the active space's color, and no longer switches light/dark per page from the page's background. That made it differ from tab to tab. The hover card is opaque too, with no translucency or blur, so the page doesn't show through. ## Site icons without favIconUrl (2026-10-25)

- **Problem:** Safari leaves `tab.favIconUrl` empty for every tab, so the sidebar only showed letters.
- **Approach (Tirth asked for real icons):** each page's content script picks its best icon link (`view.pickIconHref`: SVG or ~16–64px `rel=icon` first, then any icon, then apple-touch-icon, else `/favicon.ico`) and sends `pageIcon {href}`. The background fetches it once per site (origin): `credentials: 'omit'`, 6s timeout, ≤512KB. It checks the bytes really are an image (`icons.sniffType`, which rejects e.g. HTML error pages served as 200) and shrinks raster icons to 32×32 PNG with `createImageBitmap` + `OffscreenCanvas` (about 1–2KB). Where that isn't possible (SVG, or a format the worker can't decode) it keeps the original if ≤24KB. Then `state.favicons[origin] = { data: 'data:…', href, at }` (`rememberFavicon`, newest 150 sites). Results are re-checked after 7 days; failures aren't retried until the background restarts. If the page's icon fails, `/favicon.ico` is tried.
- **Rendering:** `view.iconFor(state, item)` uses the browser's icon if any (Chrome), else the stored data: URL for that site. It's used by sidebar rows, pins (open or closed), the palette, new-tab tiles and the archive. Showing a stored icon makes no network request. If a page's CSP blocks `data:` images in our shadow root, the `<img>` errors and the letter avatar shows.
- **Safety:** the page chooses the URL, and the background can fetch what pages can't. So icons on another host must be https and not on a local or private network (`iconUrlAllowed`). Same-host icons are always allowed. No cookies are sent.
- **SPEC change:** the "no third-party requests" rule stays; fetching the visited site's own icon is the one request Margin makes (SPEC updated).
- **Needs a Safari check:** whether the background's `fetch` reaches sites under Safari's website-access permission, and whether Safari's worker supports `OffscreenCanvas` (without it, icons are stored unshrunk up to 24KB).
