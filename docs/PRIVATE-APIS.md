# Private APIs

Every private macOS call, class, selector, key and file format Margin.app uses. Keep it up to date with every change to one of them. The code is `app/platforms/macos/private/PrivateCalls.swift` (the parts the host builds on) and `app/platforms/macos/private/HostCalls.swift` (the host's own).

Margin is hosted only since 2026-11-16 (`DECISIONS.md` "Hosted only", `docs/MARGIN-APP.md`): the profile handoff, parking of the person's own windows, the live cover and the overlay over Safari are gone, and with them every call only they made (the rows struck through below, and "Removed" at the end). What is listed as used is what the shipped code still calls.

## The rule

**No private call without a fallback and a launch check, and nothing checked that nothing calls.**

- Each call is looked up at launch, before the shell starts (`PrivateCalls.check`, then `HostCalls.check`, called from `AppDelegate.startShell` through `Shell.checkPrivateCalls`).
- Anything missing, or a type encoding that changed, turns that part off for the whole run. The person gets no notice. The log gets one line.
- A call nothing uses is not checked: a call going away in a macOS update would turn hosting off for nothing (the tile calls on 2026-11-15; the active Space read, the bridge's remove operation, the live cover's calls and the enumerator's candidate on 2026-11-17).
- Every real call is verified when it's used (the host reads the result back: a window's Spaces, its bounds, a Space's reservation). A call that didn't land fails that step: the app is shown in window mode, or not hosted.
- Every Copy function is declared as returning `Unmanaged<CFArray>?`. Nil means "unknown", never a crash.
- Tests never call a real private function and never freeze the screen:
  - the real resolver (`RealPrivateResolver`) is made only in `Shell.forApp()`;
  - it and every wrapper (`SkyLight`, `SkyLightSpaces`, `HostPrivate`, `HostAX`) refuse to run when `MARGIN_APP_TESTS` is set, and `tools/app-tests/run.sh` sets it;
  - tests use a fake resolver whose "functions" are their own (`app/platforms/macos/private/tests/private-calls-tests.swift`, `app/platforms/macos/shell/tests/host-tests.swift`).
- The log holds names, counts, results and milliseconds only. Never a title, an address or a page's words. Nothing is sent anywhere.

Notes on the rows:

- **Row 14 (geometry): `SLSGetWindowBounds`** gives the window server's model bounds, not `CGWindowList`'s animated or presentation rectangle (an owned off-screen transform control on macOS 27.2.1 (26B131), 2026-11-10, kept 800×600 model bounds while the presentation became 402×300: `tools/mission-control-lab/README.md`). `SkyLight.modelBounds(of:)` requires a nonzero connection and window, result zero and finite positive dimensions. Read only: no foreign geometry is written with it.
- **Row 12's selector is SkyLight's.** The class and its `-performWithWMBridgeDelegate` are implemented in SkyLight (read with `class_getImageName` and `dladdr` on 26B123). `WindowManagement.framework` is still opened and checked: every lab that moved a window had it loaded, and whether the bridge's delegate needs it hasn't been tested.
- **The bridge's operations are asynchronous** (their superclass is `SLSAsynchronousBridgedWindowManagementOperation`). The labs never released them. `SkyLight` and `HostPrivate` keep each one for 10 s after it's sent (`KeptOperations`), far past its step's end, instead of leaking every one. Never by count: a burst (quit's returns) can't release one still in flight. What releasing one mid-flight does is untested.
- **The initializers are called through their implementation** (`method_getImplementation`), with the receiver as a raw pointer: `init` consumes the object `+alloc` made, and may return another. They're never called when the encoding changed: the wrapper is only filled in for parts the check passed.
- **The launch line** says what was found: `private calls on macOS 27.2 (26B123): freeze ok, spaces ok, park ok, geometry ok (11/11 functions, 1/1 classes, 2/2 selectors, encodings ok); slot ok in 0.4 ms`. An off part says why: `park off: -initWithSpaceID:windows:options: encoding changed (…, expected @36@0:8Q16@24I32)`.
- **Rows 21 and 22 (the slot).** Every full-screen Space lays its window out in a tile, and its `TileLayoutManager` value holds a `ReservedArea`. Setting it makes the window manager lay the tile out again and the app size its own full-screen window to what's left: a top reservation of 8 on a display with a 33-point strip puts the window's top at 41. Any process may set it for another app's Space, with no permission. Zeros give the whole Space back. **The reservation outlives the process that set it**, unlike every other private state Margin makes, so what sets it must also reset it (the host does, at quit and after a crash: its marker). The slot's part needs the Space reads (a window's Space) and model geometry (to verify), and stays on when parking is off.
- **Rows 23-35 (the host).** Checked by `HostCalls.check` with a line of its own after the main one: `private calls (host) on 26B131: host ok (12/12 functions and keys, 2/2 selectors, encodings ok); outside opens ok`. Codes heard: 659 an open request from outside, 561 the no-Dock instance promoted to a normal app (`docs/MARGIN-APP.md` item 4: detected and logged, kept hosted; what Margin does then is open). Only apps Margin started are launched, put in full screen, parked or quit; the only exception is a Safari window Margin's own extension made in a Safari already running, which is put in full screen, sized by its own Space's reservation (row 21) and moved into Margin's Space as a member (the bridged move, options 7, as proven on 2026-11-15 by `/tmp/margin-toolbar-test/mc/mc8`, `mc10`), its own Space then destroyed (rows 28-29), and at the end out of full screen and closed by the extension, never quit. A crash marker (`hosted.json`: pids, bundle ids, launch times, window and Space numbers) is read at the next launch.
- **Rows 22-23 and 36-39 (the tiles, live resize).** Their own words at the end of the host's line: `…; outside opens ok; tiles ok`, or `tiles off: SLSBridgedSpaceSetValuesOperation missing`. The bridged destroy (rows 28-29) also takes a hosted tile its window left behind (an app killed leaves a placeholder: the kit's l3y), at the next look and at a crash's recovery. Margin's Space never gets a reservation (row 21) while tiles are in it: any reservation, tile added or tile taken out re-lays its first two tiles as a split's halves. Margin killed leaves its Space with no owner and the hosted tiles in a visible split until the next launch's recovery.
- **Rows 40, 41, 43 also serve a split's cut pane (docs/PEEK-SPLIT.md §4b), whatever the all-panes-active setting
  (`HostSystem.paneDelivery`: the activator, the records' layout passed, none refused).** Row 43 with option 0x400
  (kCPSNoWindows): its app made the front one with its windows left in the window server's order (`PaneActivator.
  focusWithoutRaise`, then row 40's make-key pair). Row 41 reads a press's own record and row 40 posts it to the cut
  pane's app with its window at 0x3c and its point in that window (top left) as doubles at 0x20 and 0x28
  (`PaneRecords.delivered`, `PaneActivator.deliver`): the press, its drags and its release reach that window, nothing
  raised (2026-11-22, 26B131, Chameleon test copies in Margin's Space). Refused: the press routed as before.
- **Row 41 isn't used for a press on Margin's own panel (docs/SIDEBAR-PRESS.md, GitHub #29).** The
  press is delivered to Margin's panel as an event made afresh with public calls (`NSEvent.mouseEvent` for the panel,
  `NSApp.postEvent` in Margin's own queue: PaneClickTap.swift `PanelEvents`), never as its own record: posted as
  its record (row 40, the first build), the press keyed the panel inside AppKit and took Margin for active (the real
  screen, 2026-11-24). Its first press's record was read for the log (its bytes 0x38-0x3b) while the cause was looked
  for; that read is gone (2026-11-25, the merge review: a private call for a log line only).
- **Rows 40-45 (all panes active).** Their own words at the end of the host's line: `…; anchors ok; panes active ok`, or `panes active off: SLPSPostEventRecordTo missing` / `…: the event records' layout isn't the one checked (an AppKit-defined event's window at 0x3c 0x0, expected 0x5a17)`. The make-key flag (0x3a = 0x10) can't be built with a public call, so the check can't see it change: it's yabai's and AltTab's, and the research's. Two panes of one app can't both be active (one key window per app): never tried. Not used, and why: `SLSSetWindowHasKeyAppearance` and `SLSSetWindowActive` sent from another process do nothing (allfocus e3f, e4c); `SLPSStealKeyFocus`/`SLPSReleaseKeyFocus` not needed (the keyboard stays the front process's); `SLPSGetKeyFocusProcess` not called (it takes two pointers: declared with one it crashes).
- **The macOS build** (`kern.osversion`) is kept in `UserDefaults` as `MarginPrivateCallsBuild`. A new one adds `private calls: macOS build changed from 26B123 to 26C45: private calls checked again`. Every launch checks everything anyway.
- **The freeze can't be verified by the product**: whether the screen really holds still needs a screen capture, and screen recording is ruled out of the mechanism.

## Considered, not used

- `SLSOrderWindow`, `SLSMoveWindow`, `SLSSetWindowAlpha`, `SLSSetWindowLevel`, `SLSSetWindowTags` and other direct window calls on another process's window: refused across processes with error 1000, or silently ignored (the cross-process lab, `xp.swift`, 2026-11-06).
- `SLSAddWindowsToSpaces`, `SLSRemoveWindowsFromSpaces`, `SLSMoveWindowsToManagedSpace`, `SLSSpaceAddWindowsAndRemoveFromSpaces`, `SLSSetWindowListWorkspace` (the direct, non-bridged Space calls): tried in the same lab. The bridge (rows 10 and 12) is the form every later lab used to move another app's windows.
- `SLSBridgedMoveWindowsToManagedSpaceOperation`: replaced by row 10, which gives each parked window its own private Space.
- `SLSSpaceTileMoveToSpaceAtIndex`, `SLSSpaceSetInterTileSpacing` (rows 24-25, the direct functions): the first build's tiles, retired 2026-11-15; the tiles came back on 2026-11-17 through the bridge (rows 36-39), with `SLSSpaceCopyTileSpaces` (row 23).
- `SLSSetWindowHasKeyAppearance`, `SLSSetWindowActive` (a window's key look and active state set from another process): no effect on the other app's window (the panes-active research, allfocus e3f and e4c, 2026-11-21). The records (rows 40-45) are what AppKit listens to.
- `SLSSpaceSetValues` (direct): ignored for another process's tiles (the live-resize kit, l3b a, 2026-11-17). `SLSTileSpaceMoveSpacersForSize`: no effect on a custom tile rect (same run).
- Minimizing, Desktop parking, AppleScript, and screen recording in the mechanism: ruled out.

## On a macOS beta

The handoff's lab tool (`tools/handoff-lab/`) was removed with the handoff on 2026-11-16; its runbook and reports (26B123 of 2026-11-06, 26B131 of 2026-11-10) are in git history. The calls above are the same ones it ran. What is left to do on a new build:

1. Read both launch lines (below, "What to watch"): every part `ok`, the counts as above.
2. **A changed encoding or a missing call**: record the new encoding here, find whether the call's arguments changed, and only then change `PrivateCalls.selectors` or `HostCalls.selectors`. Never just copy the new encoding in.
3. Anything on the real screen (an app hosted, Safari hosted) only with Tirth's OK: one dry run first, and stop at the first failure.
