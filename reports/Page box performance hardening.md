# Harden Margin by preparing every frame

Margin keeps the in-place page-box direction, removes its transient child markers, makes dynamic CSS bookkeeping follow the live rule graph, and prepares a destination before Safari activates it. The initially preferred all-private body-read transaction was rejected after measuring the real bundle: on WebKit, an ordinary dirty read rose from roughly 1 ms to 5 ms and a 20,000-row/3,000-rule read from roughly 14 ms to 65 ms. A second isolated harness agreed on the ordering: a random `<head>` attribute was about 9 ms for 150 reads, while private sheet disable/enable was about 23 ms and selector/media/rule replacement variants about 32–34 ms. The shipped design is therefore deliberately engine-specific: **Chromium uses private CSSOM, while WebKit uses a random per-document `<head>` attribute for the duration of one synchronous read and permanently falls back to private CSSOM if the page reacts to it.** This leaves the tree shape untouched, avoids custom-element and child-list callbacks, and retains WebKit's fast path.

Dynamic CSS moves from append-only global bookkeeping to live, per-sheet metadata reconciled in batches, while viewport-sensitive author input is still rewritten before native parsing. An extension-initiated switch preflights the hidden destination, applies an authoritative background-state snapshot, drains its pending sheet and geometry work, and publishes the preparation token only after the final acknowledgement layout. A private constructed cover sheet handles never-shown arrivals without mutating the page's inline style. There is no standards-level callback guaranteed to run before the first presented frame of every native tab activation, so “no flicker” means **no stale or incorrectly sized extension-prepared frame**; a frozen, discarded, inaccessible, or manually selected tab remains a browser boundary and may require a short cover or its synchronous visibility repair.

## An engine-specific read transaction removes the child markers

The architecture retains the existing `::backdrop` cascade reader but changes how Margin temporarily removes its own fit declarations. There is no interoperable private selector state for an ordinary `<html>` or `<body>`: custom states belong to custom-element internals, and constructing or connecting a custom element can synchronously invoke author lifecycle code ([HTML custom states](https://html.spec.whatwg.org/multipage/custom-elements.html#custom-state-pseudo-class); [HTML custom-element reactions](https://html.spec.whatwg.org/multipage/custom-elements.html#custom-element-reactions)). The old child markers necessarily changed structural selectors and enqueued child-list records, because DOM mutation delivery explicitly covers child insertion and removal ([DOM mutation observers](https://dom.spec.whatwg.org/#mutation-observers)). A permanent marker was rejected for hydration and serialization correctness.

Chromium holds the fit and transition-suppression rules in private constructed sheets and switches them through captured native CSSOM descriptors inside one synchronous task. WebKit instead gates those same rules on a random attribute of the existing `<head>`: the attribute moves from `read` to `hold` and is restored before the task returns. This changes neither child order nor any `body:last-child`, sibling, hydration, serialization, or custom-element condition. A page can observe the head attribute, so Margin snapshots `<html>`/`<body>` author attributes before the read; if an observer reacts by changing either, that document moves permanently to the private path and the feedback stops. A missing, replaced, or non-preceding `<head>` also takes the private path. CSSOM defines the private mutation surfaces used by the fallback ([CSSStyleRule](https://drafts.csswg.org/cssom/#the-cssstylerule-interface); [CSSStyleSheet](https://drafts.csswg.org/cssom/#the-cssstylesheet-interface)).

The transaction enables transition suppression, switches off only Margin's body-fit declarations, reads authored values through the existing boxless pseudo, restores the fit declarations, publishes the newly resolved geometry, performs only the application read proved necessary by engine tests, and then releases suppression. Nested `try/finally` blocks restore every sheet and attribute even if a detached body or hostile page behavior causes an exception. Everything occurs without an awaited promise, timer, animation frame, or intermediate render opportunity. Captured native descriptors prevent page wrappers from altering the transaction. Margin does not reimplement the cascade: `getComputedStyle()` returns resolved values and can expose used widths, while the true cascade includes inaccessible cross-origin rules, origins, layers, animation and transition states ([CSSOM resolved values](https://drafts.csswg.org/cssom/#resolved-values); [CSS cascade origins](https://drafts.csswg.org/css-cascade/#cascading-origins)). The `::backdrop` technique remains the engine-assisted reader; only its mode switch changes.

Engine cost is not standardized, and the measurements show why a single mechanism is the wrong abstraction. Blink documents that inherited changes can cause subtree recalculation whereas narrower invalidations can stop earlier, explaining why superficially equivalent switches have very different cost ([Blink style recalculation](https://chromium.googlesource.com/chromium/src/+/c4474d7b8c2fc6e656bdf4c08bf775ce0fa096ee/third_party/WebKit/Source/core/style/stylerecalc.md)). Both selected paths are tested against `body:last-child`, document structure, observer feedback, over-constrained widths, negative and automatic margins, RTL, scrolling, transition suppression, and active animations. Corrected CSS width arithmetic preserves overflow and negative used margins instead of clamping every over-constrained body to the virtual viewport.

## Live sheet metadata closes dynamic CSS gaps

MutationObserver cannot observe stylesheet rule edits, constructed-sheet mutation, or adopted-sheet array mutation; its record types stop at DOM tree, attributes, and character data ([DOM Standard](https://dom.spec.whatwg.org/#interface-mutationobserver)). The CSSOM and Typed OM expose several independent mutation surfaces, including top-level and grouping-rule insertion/deletion, sheet replacement, selector and declaration changes, `StylePropertyMap.set`/`append`/`delete`/`clear`, media-list mutation, and the observable-array semantics of `adoptedStyleSheets` ([CSSOM interfaces](https://drafts.csswg.org/cssom/#the-cssstylesheet-interface); [Typed OM style maps](https://drafts.css-houdini.org/css-typed-om/#stylepropertymap); [adopted stylesheets](https://drafts.csswg.org/cssom/#extensions-to-the-documentorshadowroot-interface)). **Hooks should detect these operations, but they should do almost no expensive work themselves.** Each same-origin live sheet should have a weakly held metadata record and monotonic revision; one coalesced pass atomically replaces that record with the sheet's current viewport-unit, media-holder, and geometry-relevant selector facts. This mirrors Blink's own approach of accumulating invalidations and delaying recalculation until the render path needs it ([Blink style invalidation](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/css/style-invalidation.md)). Deleted rules then disappear naturally, eliminating the current unbounded `:has()` history.

Viewport-sensitive text passed to `insertRule` or `replaceSync` still needs rewriting before native parsing so an incorrect `100vw` cannot reach a paint. Grouping-rule insertion must use the same path as top-level insertion. Retained rule declarations and typed maps should be associated with their owner rules through weak maps when getters return them; their actual mutators—not merely those getters—then mark the correct sheet dirty even hours later. Every registered `Document` or `ShadowRoot` needs the same ordinary-sheet and adopted-sheet reconciliation. Patching `attachShadow` at document start retains future open and closed roots, while bounded lifecycle scans discover existing open roots. Root replacement must atomically rebuild observers and registries, and every viewport or coordinate shim must query one live root accessor instead of closing over the original document element.

The final retained-declaration hook uses one shared child prototype per page, populated from that browser's own named-property accessors. It leaves `CSSStyleDeclaration.prototype` and every `element.style` write native, and it avoids allocating an accessor table per rule. In the same Chromium harness, the rejected per-declaration form took about 595 ms and 34 MB for 1,000 declarations, while the shared form took about 0.7 ms and 39 KB. Sheet lifecycle metadata also stores both the immediate sheet and its top-level owner: `replaceSync`/`replace` restore detached retained media rules, and removing or rescanning an `@import` owner evicts its imported child sheets before the next walk. This prevents both retained strong-ledger entries and restored-but-never-reshifted imported queries.

`:has()` requires a deliberately conservative policy. Pseudo-classes represent state outside the document tree, and `:checked`, focus, hover, active and similar state can change without any mutation record ([Selectors Level 4](https://drafts.csswg.org/selectors/#pseudo-classes); [WPT dynamic state in `:has()`](https://github.com/web-platform-tests/wpt/blob/master/css/selectors/invalidation/user-action-pseudo-classes-in-has.html)). Relevant selectors should therefore live only in current sheet metadata, be evaluated against the complete body-reachable collapse chain, and trigger at most one coalesced check or conservative body read after relevant interaction and state-setter hooks. A conservative read is preferable to matching thousands of accumulated selectors. No browser exposes a generic style-invalidation observer, so Margin can cover known live pseudo-states without honestly claiming proof against every future UA-driven state.

## Prepared generations make clean switches effectively free

Page activation cannot be repaired reliably by moving more work into `visibilitychange`. HTML changes visibility by queuing a task, while hidden documents are excluded from normal rendering updates; the platform does not promise that this task runs before every first frame the browser UI presents ([HTML page visibility](https://html.spec.whatwg.org/multipage/interaction.html#page-visibility); [HTML rendering updates](https://html.spec.whatwg.org/multipage/webappapis.html#update-the-rendering)). Background tabs can also lose animation frames, have timers throttled, become frozen, or be discarded ([Chrome background tabs](https://developer.chrome.com/blog/background_tabs); [Chrome Page Lifecycle](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)). **The fast path must therefore be a tab whose geometry is already current, not a tab that computes geometry when it becomes visible.**

Margin should maintain a compact generation vector covering document/root identity, virtual box dimensions, live-sheet revision, body-state revision, and last applied geometry. Hooks update generations immediately—even while hidden—and perform only bounded reconciliation in the same turn or microtask. A clean generation activates with zero body reads or reconciliation work and no delayed `rest()` work; the implementation still performs one deliberate host-rectangle acknowledgement layout before returning across processes. When Margin itself initiates a switch, the background/UI side asks the destination to prepare its current generation, publish all final CSS state in one synchronous commit, force that one engine-proven acknowledgement layout, and return a token; activation proceeds only if that token still matches. Because browsers do not render halfway through a JavaScript task, this prevents partially updated geometry ([HTML event loops](https://html.spec.whatwg.org/multipage/webappapis.html#event-loops)). It also removes the current duplicate enable/fullscreen reads: lifecycle handlers invalidate once, and the generation reconciler owns the single resulting measurement.

Native browser-tab selection has no portable destination-preflight event. A hidden tab that becomes dirty must therefore either remain cheaply prepared or already have an extension-owned opaque cover armed before activation. On visibility, Margin synchronously validates, publishes and removes that cover; if presentation beats the task, the first frame is the cover rather than stale padding, wrong content width, or an unboxed page. A frozen or discarded process cannot promise both an immediate destination and executable repair code, so this is a real platform boundary rather than an optimization failure. `requestAnimationFrame` cannot solve it because background tabs do not receive callbacks; `scheduler.postTask` is not render-blocking or cross-browser; View Transitions intentionally snapshot and animate the page, adding GPU and memory work ([Chrome timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88); [Prioritized Task Scheduling](https://wicg.github.io/scheduling-apis/); [View Transitions](https://www.w3.org/TR/css-view-transitions-1/)). The implementation uses an already-adopted private constructed sheet to cover the body, with transition suppression in the same sheet. It verifies the resulting computed opacity; an older page-world script, or an authored inline `!important` rule that defeats the private sheet, uses a token-owned inline fallback whose original value and priority are restored on cancellation.

## Five gates turn the redesign into evidence

Implementation proceeds as a sequence of reversible gates, keeping `main` and the present feature commit as benchmark controls. The first gate commits adversarial tests before changing behavior: structural body selectors, pre-defined old marker names, MutationObserver echo, fixed and over-constrained geometry, retained CSS declarations, nested rules, prebuilt adopted sheets, shadow roots, root replacement, state-only `:has()`, scroll locks, transitions, and animation counts. The second gate benchmarks and lands the per-engine read transaction only if it removes every child-marker side effect while retaining the current WebKit advantage. The third gate corrects width resolution and introduces the live root, root registry, weak sheet metadata, complete CSSOM mutator coverage, and bounded `:has()` lifecycle. The fourth gate replaces visibility-time repair with the generation/preflight/cover protocol. The fifth gate removes redundant work and profiles selector batching, animation discovery, bundle parse/evaluation, memory retention and compositor behavior.

| Gate | Required release evidence |
|---|---|
| Read transaction | Zero child-list/tree-shape mutations per read; transient WebKit head-attribute records detected with a permanent private fallback; no structural-selector, hydration, custom-element or transition regression; native-equivalent geometry in Chromium and WebKit |
| Dynamic CSS | Top-level and nested CSSOM, retained declaration/Typed OM, media, adopted-sheet and shadow-root fixtures pass; insert/delete churn returns metadata to baseline |
| Geometry | A native unboxed oracle agrees for fixed, minimum, maximum, percentage, intrinsic, negative, auto, RTL and overflowing body shapes; scrolling and root replacement remain coherent |
| Activation | Clean switches perform zero body measurements/reconciliation plus one acknowledgement layout; dirty extension switches prepare before activation; hundreds of captured switches contain zero stale/wrong-geometry frames |
| Resources | Idle work is zero; one reconciliation/read maximum per mutation batch; load and switch p50/p95/p99 do not regress; peak and settled RSS, JS heap, style/layout, paint, raster and GPU measurements stay within explicit budgets |

The activation gate must score browser-presented frames rather than infer success from event ordering. Chrome DevTools exposes frame, GPU, raster and screenshot data, and CDP can activate a tab and stream screencast frames with viewport timestamps ([Chrome Performance panel](https://developer.chrome.com/docs/devtools/performance/reference); [Chrome DevTools Protocol Page](https://chromedevtools.github.io/devtools-protocol/tot/Page/)). Safari Web Inspector can capture screenshots after composites and correlate them with style recalculation, layout, paint and frame work ([WebKit Timelines](https://webkit.org/web-inspector/timelines-tab/)). Stable fixtures should include colored frame edges, corner markers, fixed and viewport-unit elements, scroll markers and a frame-sequence value so each captured frame can be classified as old source, cover, stale geometry, correct destination, or blank. Tests should randomize native/no-extension, `main`, current feature and candidate builds; report distributions and zero-failure counts over hundreds of switches; and commit fixtures, raw samples, traces and analysis scripts. Unit, WebKit-host, Chromium E2E, real Chrome and real Safari results are all required because headless DOM assertions cannot prove what the compositor presented.

## Platform boundaries require explicit degraded modes

Exact handling is attainable for same-origin document sheets, open roots, future roots captured at `attachShadow`, and early-installed hooks. It is not attainable from page JavaScript for pre-existing or declarative closed roots, because a closed root is deliberately absent from `host.shadowRoot`, or for origin-unclean stylesheet rules, where CSSOM access throws `SecurityError` ([DOM shadow roots](https://dom.spec.whatwg.org/#dom-element-shadowroot); [CSSOM `cssRules`](https://drafts.csswg.org/cssom/#dom-cssstylesheet-cssrules)). Early document-start injection is therefore a functional requirement. After extension update or late injection, existing closed roots require reload for exactness. Cross-origin sheet copying remains an extension-fetch path with explicit checks for imports, relative URLs, credentials, CSP, cascade order and failure restoration; when semantic reproduction fails, the UI and tests must call it degraded rather than silently claiming a generic virtual viewport.

These limits sharpen the product guarantee. Margin can promise that supported live state never presents a known stale geometry frame and that clean prepared switches add essentially no page work. It cannot promise that suspended or discarded code executes before browser UI presentation, that inaccessible closed trees can be retroactively virtualized, or that every future pseudo-class emits an observable signal. The cover/reload/degraded paths convert those impossible cases into controlled behavior instead of intermittent flicker or silently incorrect content size.

## Conclusion

The decisive change is not a lower-level language or a faster arithmetic routine; it is moving correctness off child markers and moving activation work out of the first visible frame. An engine-selected synchronous transaction, live revision metadata and prepared-generation protocol align the design with how browser engines already batch style invalidation while keeping the page's tree shape untouched.

This architecture also makes performance falsifiable. If every clean switch has zero reads, every dirty batch has at most one, metadata returns to baseline after churn, and captured Chromium and Safari frames never show stale geometry, Margin has achieved a materially stronger result than another synthetic load-time improvement. Where the browser withholds execution or access, an already-armed cover or explicit reload is the only honest no-wrong-frame answer.
