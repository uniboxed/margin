# The page box: its rules and its cases

The page box is how Margin fits a web page beside its sidebar with no iframe. `<html>` becomes a box at the slot the theme leaves for the page, `<body>` scrolls inside it, and what the page asks about its window is answered for the box.

This folder says what the box promises, as rules, and holds a case for every edge it handles. Each case is a small page that shows one thing a real site does.

## The box's code

| File | What it does |
| --- | --- |
| `extension/shared/page-box.js` | The box's CSS as text: `<html>`'s rule (`BOX_ROOT`, weighted so a page's classes can't beat it), `<body>` as the scroller, full screen, the first paint's version of the same rules. |
| `extension/shared/page-css.js` | Rewrites a page's CSS for the box: media queries about the window's size, and `vw`/`vh` units. Pure text, tested in node. |
| `extension/content/page/main.js` | Starts the box in the page's own world. |
| `extension/content/page/box.js` | Puts the box's sheets in, moves the box when the layout changes, and does by hand what a real window's root does: the scroll handed to `<body>`, the page's scroll locks, things put directly under `<html>`. |
| `extension/content/page/sheets.js` | Finds the page's style sheets and style attributes that changed, and has them rewritten (page-css.js). |
| `extension/content/page/viewport.js` | Answers for the box what a page asks about its window: `innerWidth`, scrolling (the window's is `<body>`'s), `scrollingElement`, paging keys, the place kept across Back and reload. Keeps the window itself unscrolled. |
| `extension/content/page/coords.js` | Client coordinates from the box's corner, not the window's: `getBoundingClientRect`, points, mouse events. |
| `extension/content/page/media.js` | `matchMedia` about the window's width asks about the box's. |
| `extension/content/page/in-view.js` | `IntersectionObserver` with no root sees the box's edges. |
| `extension/content/page/top-layer.js` | Dialogs and popovers (the top layer ignores `<html>`'s transform) placed against the box. |
| `extension/content/page/moves.js` | Which transitions and animations are on their way, from the page's own events, for box.js's reads. |

## The rules

Every case is held to every rule. A rule compares the page in its box with the same page in a plain window the box's size: an iframe that size, in the same browser (`serve.js`, `/ref/`).

<!-- rules: generated by tests/box/readme.mjs -->
- `box-at-slot`: `<html>` is drawn at the slot's corner (the box's place beside the sidebar).
- `box-size`: `<html>` is the slot's size: whatever the page says about `<html>`'s size, place or margins.
- `told-size`: what the page is told its window is (innerWidth, innerHeight) is the box it is drawn in.
- `window-still`: the window itself never scrolls: `<body>` does (a page focusing something out of sight mustn't slide the box).
- `body-scrolls`: `<body>` is the scroller (document.scrollingElement).
- `no-overflow`: nothing runs past the box sideways that wouldn't run past a plain window.
- `same-layout`: every element is where, and the size, it is in a plain window (as the page sees it).
- `same-scroll`: the page is scrolled where it would be in a plain window.
- `same-answers`: what the page wrote down in its `<output>`s (media queries, sizes, events) is what it writes in a plain window.
<!-- /rules -->

`rules.js` holds them as two self-contained functions: `measure()` runs in a page, and `judge(boxed, plain, setup)` lists the rules broken. The same code runs in both engines.

## Adding a case

1. Make the smallest page that shows it, `cases/<name>.html` (lowercase, dashes), starting with its header:

   ```html
   <!--
   case: what it holds, in a line
   from: where it came from (a site and a fit-check round, a report, a review)
   handled-by: the box's file(s) that handle it
   settle: 600
   -->
   <!doctype html>
   ```

   `settle` is how long after the page's load to wait before measuring (default 500 ms). A page that does something after load (scrolls, opens a dialog, focuses a link) does it itself, in a script.
2. To check what the page sees, not only where things are, have it write its answers into `<output id="…">` elements. Media-query answers, sizes it was told, events it got: `same-answers` compares them with the plain window's.
3. Run it and watch it fail (a case for a bug fails before the fix), then fix the box until it passes.
4. `node tests/box/readme.mjs` puts it in the table above. `npm test` fails while the table is out of date.

Two optional fields:

- `allow:` lets a case off a rule (`allow: same-scroll`), or one element or output (`allow: same-layout #ad`). Only for a difference that's meant to be there, said in `note:`.
- `engines: chromium` or `engines: webkit` runs the case in one engine only. Leave it out for both.

## Running them

```sh
node --test tests/e2e/box-cases.test.js     # Chromium (part of npm run test:e2e)
tools/webkit-host/run.sh box-cases          # Safari's engine (part of npm run test:webkit)
```

Chromium runs them through the e2e harness: the test build of the extension, the stand-in Margin.app, the sidebar kept open (the slot 260/8/8/8 in a 1440×900 window). The WebKit host does the same in Safari's engine (a 1200×800 window). Both serve the cases with `serve.js`.

## The box's other tests

The cases are for what a page looks like and is told in the box. What the box does over time and with the rest of Margin stays where it was tested before:

- Unit (node): `tests/page-css.test.js` (the CSS text and its rewriting), `tests/page-reads.test.js`, `tests/page-moves.test.js`, `tests/page-upkeep.test.js`.
- e2e: `tests/e2e/page-box.test.js`, realistic sites in the box, live layout changes, frames, first frames.
- WebKit host (`tools/webkit-host/scenarios.mjs`): `box`, `toggle`, `csp`, `lock`, `late-body`, `read-limits`, `late-reads`, `read-shape`, `body-size`, `body-background`, `in-view`, `answers`, `top-layer`, `first-paint` and others (its README lists them).

## Where cases come from

`tools/fit-check` loads the top 10,000 sites each night through the box and plain. When a site breaks a rule there, the smallest page that does what the site does becomes a case here: the fix and its guard go in together.
