# The page box: its rules and the patterns it handles

The page box is how Margin fits a web page beside its sidebar with no iframe. `<html>` becomes a box at the slot the theme leaves for the page, `<body>` scrolls inside it, and what the page asks about its window is answered for the box.

This folder says what the box promises, as rules, and lists the page patterns it handles. A pattern is something pages commonly do that the box has to get right: a class on `<html>`, a menu slid in from off-screen, a modal that locks scrolling. Each pattern is a small page that does just that, and each fix is made at the root, for every page that does it, never for one site.

## The rules

Every pattern is held to every rule. A rule compares the page in its box with the same page in a plain window the box's size: an iframe that size, in the same browser (`serve.js`, `/ref/`). Because the rules hold for any page, they also catch what no pattern covers yet: fit-check holds the box to the same promises on real sites.

<!-- rules: generated by tests/box/readme.mjs -->
- `box-at-slot`: `<html>` is drawn at the slot's corner (the box's place beside the sidebar).
- `box-size`: `<html>` is the slot's size: whatever the page says about `<html>`'s size, place or margins.
- `told-size`: what the page is told its window is (innerWidth, innerHeight) is the box it is drawn in.
- `window-still`: the window itself never scrolls: `<body>` does (a page focusing something out of sight mustn't slide the box).
- `body-scrolls`: `<body>` is the scroller (document.scrollingElement).
- `no-overflow`: nothing runs past the box sideways that wouldn't run past a plain window.
- `same-layout`: every element is where, and the size, it is in a plain window (as the page sees it).
- `same-scroll`: the page is scrolled where it would be in a plain window.
- `same-answers`: what the page wrote down in its `<output>`s (media queries, sizes, events) is what it writes in a plain window.
<!-- /rules -->

`rules.js` holds them as two self-contained functions: `measure()` runs in a page, and `judge(boxed, plain, setup)` lists the rules broken. The same code runs in both engines.

## Adding a pattern

1. Make the smallest page that does what pages do, `patterns/<name>.html`. Name it after the pattern, not the site (lowercase, dashes). Start it with its header:

   ```html
   <!--
   pattern: what pages do, and what the box keeps true for them, in a line
   from: where it was first seen (a site and a fit-check round, a report, a review)
   handled-by: the box's file(s) that handle it
   settle: 600
   -->
   <!doctype html>
   ```

   `settle` is how long after the page's load to wait before measuring (default 500 ms). A page that does something after load (scrolls, opens a dialog, brings a link into view) does it itself, in a script.
2. To check what the page sees, not only where things are, have it write its answers into `<output id="…">` elements. Media-query answers, sizes it was told, events it got: `same-answers` compares them with the plain window's.
3. Run it and watch it fail (a new pattern the box gets wrong fails before the fix), then fix the box at the root until it passes.
4. `node tests/box/readme.mjs` puts it in the table above. `npm test` fails while the table is out of date.

Two optional fields:

- `allow:` lets a pattern off a rule (`allow: same-scroll`), or one element or output (`allow: same-layout #ad`). Only for a difference that's meant to be there, said in `note:`.
- `engines: chromium` or `engines: webkit` runs the pattern in one engine only. Leave it out for both.

## Running them

```sh
node --test tests/e2e/box-patterns.test.js   # Chromium (part of npm run test:e2e)
tools/webkit-host/run.sh box-patterns        # Safari's engine (part of npm run test:webkit)
```

Chromium runs them through the e2e harness: the test build of the extension, the stand-in Margin.app, the sidebar kept open (the slot 260/8/8/8 in a 1440×900 window). The WebKit host does the same in Safari's engine (a 1200×800 window). Both serve the patterns with `serve.js`.

## The box's other tests

The patterns are for what a page looks like and is told in the box. What the box does over time and with the rest of Margin stays where it was tested before:

- Unit (node): `tests/page-css.test.js` (the CSS text and its rewriting), `tests/body-fit.test.js` (`<body>`'s arithmetic), `tests/page-reads.test.js`, `tests/page-moves.test.js`, `tests/page-upkeep.test.js`.
- e2e: `tests/e2e/page-box.test.js`, realistic sites in the box, live layout changes, frames, first frames.
- WebKit host (`tools/webkit-host/scenarios.mjs`): `box`, `toggle`, `csp`, `lock`, `late-body`, `read-limits`, `late-reads`, `read-shape`, `body-size`, `body-background`, `in-view`, `answers`, `top-layer`, `first-paint` and others (its README lists them).

## Where patterns come from

`tools/fit-check` loads the top 10,000 sites each night through the box and plain. When a site breaks a rule there, what it does is boiled down to the smallest page that does the same, and that page becomes a pattern here: the fix and its guard go in together.
