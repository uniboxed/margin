## Investigation notes (before a real browser switch)

The first four failures happened before posting any switch. Owned-window registration was absent until AppKit's transaction flushed. The `add`/`show` error labels came from obsolete Int32-return prototypes; local read-only disassembly of the current SkyLight wrappers shows Void asynchronous mutators, so those values were not valid failure statuses. An invisible owned-window probe then established level 400 and membership only with mask 15 (mask 7 intentionally excludes private Spaces); after destruction the getter returned level 0. Source and log: `/tmp/margin-cover-membership.swift`, `/tmp/margin-cover-membership.log` (local ephemeral evidence, not committed UI content).

The fifth attempt reached the visible cover and the recorder accepted a complete cover frame. Its first requested browser switch was refused by the installed dev hook: two saved links were named Test B because the hook used historical `browserNames` aliases. No browser switch executed. The candidate uses Safari's current `windowNames` mapping, keeping genuine duplicate profiles refused. Every attempted cap was restored and each owned panel ordered out before destroying its Space. No physical-camera result is claimed.
