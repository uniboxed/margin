# WebKit host

A small stand-in for Safari, for testing Margin on Safari's own extension engine without opening or automating Safari.

It is a macOS command-line program (`host.swift`) built on WebKit's `WKWebView` (the page engine) and `WKWebExtensionController` (the extension engine Safari uses: content scripts, the background service worker, `browser.*` APIs, registered scripts). It loads Margin's Safari build (`dist/safari`) into one window with a few tabs, plays a scenario (open tabs, install or update Margin, switch tabs, put a tab to sleep, run JavaScript in a page, take a screenshot), and checks the results. The window is off screen and the program never becomes the active app, so nothing appears while it runs.

## Running it

```sh
npm run build                         # the host tests dist/safari
tools/webkit-host/run.sh all          # every scenario; exits 1 if a check failed
tools/webkit-host/run.sh switching    # one scenario
npm run test:webkit                   # the same as `run.sh all`
```

Needs macOS with Xcode's command-line tools (`swiftc`) and Node. `run.sh` compiles the host into `build/` when `host.swift` changes, copies `dist/safari` to `build/ext` with a small hook (`hook.js`) that sends Margin's console output to the test server, starts the server (`server.mjs`, port 47811, serving the test pages), runs the scenario and prints both logs: the host's steps with each check's `PASS`/`FAIL`, then Margin's console.

## Scenarios

In `scenarios.mjs`, each a list of steps (documented at the top of the file). A check (`check` in Margin's content-script world, `checkPage` in the page's) waits until its JavaScript returns `true`, up to a timeout, so scenarios don't depend on fixed waits.

| Scenario | What it covers |
| --- | --- |
| `switching` | Pages open at install get Margin (WebKit adds the core, the background the theme); switching through Margin, including to a tab Safari unloaded |
| `update` | Margin updated while a page with a typed draft is open: the new copy takes over, the draft stays, one sidebar shows |
| `box`, `hidden-box`, `toggle` | The page's box with Keep open and hidden, live toggling, the scroll handed over, media queries and viewport units, no box and nothing loaded |
| `csp`, `lock` | A strict CSP; a page's scroll locks (a body pinned with `position: fixed` too), modals, stray absolute elements |
| `late-body` | Styles for `<body>` that arrive after `load`, read again; nothing moves on a page in use. |
| `read-limits` | What a read has to get right, one check per thing a review found: lengths on their way, first children and collapsing, zoom, box moves across media queries, every way of editing styles, `:has()` turning true, and nothing moving, scrolling or waking an observer on a page in use. |
| `late-reads` | The read itself: `body:has()`, `sheet.disabled`, `rule.style`, a `<style>`'s text; lengths worked out with no layout; a modal first child; running transitions; reads backing off. |
| `read-shape` | What a page finds in its own document: `<html>`'s children and their order, what it serializes, a new `<html>` by `replaceChild` or `document.write`, a stray second `<body>`; `zoom` on `<html>` from a class; first children that stop or are stepped over; lengths that move by their own route; `addRule` and `selectorText`. |
| `body-size` | `<body>`'s own size in the box: centred columns before and after a sidebar resize, flex columns and percent heights that grow, an app that fills the window |
| `in-view` | IntersectionObserver with no root: fixed targets, `<body>`, the page's margin, entries in the page's coordinates, the box going off, a swapped `<body>` |
| `answers` | `offsetHeight`, `caretPositionFromPoint`, viewport units a script sets on elements already there |
| `keys`, `history`, `top-layer`, `linked-sheet` | ⌘↓ and ⌥↓ with nothing pressed, a pressed pane, Shift and an arrow; same-document Back and Forward; dialogs and popovers against the box; a fetched sheet following its link |
| `update-old-layout` | Pages an old copy laid out stay out of the page's script's and the placeholder's reach |
| `pinch`, `pinch-box` | Safari's pinch on a page with no box; Margin's on one with a box, the sidebar staying put |
| `newtab` | The new-tab page loads the active theme's module and draws the launcher |
| `unloadedlate`, `loadcover`, `behindlate` | A page all there at once whose load comes late (`/p/Z…`: an image that takes 3 s): a tab Safari unloaded is shown once it has painted, introduced, its content there as it's shown; one shown without loading it behind lifts its cover at its first paint; a new tab from the palette comes to the front at its first paint |
| `shelllate`, `shellcover`, `shellbehind` | An app's page (`/p/Y…`: an empty body its script fills 0.25 s later, its load at 3 s), where Margin's own sidebar or cover is the page's first contentful paint: restored, uncovered, or brought from behind once its own content is there, not at Margin's paint |
| `restartrepair` | A relaunch with tabs Safari unloaded: the repair of the open tabs asks each once, in its first pass, and none again after; a switch to one, asked as Margin starts, isn't held up and is restored behind the page |
| `unseen` | The tab in front at a relaunch (its view in the window before its process, its page made from its saved history), switched away from and back to: introduced first, its content there on its first return; no error from Margin reaches the page |
| `catchup`, `catchup-loaded`, `catchup-slow`, `catchup-late` | A hidden tab's page catches up in its preparation, before it's shown: a sheet added while hidden rewritten for the box, its box moved and rested (media lists, one resize), the read of `<body>` it asked for; a tab opened behind, introduced and arriving covered, makes its owed read before it's shown, none as it comes into view; a page whose resize listener takes 1.2 s answers the preparation in time (its listeners in a task of their own), the sidebar it carried open; a preparation with little time left leaves the catch-up to the show |
| `navigated` | The tab in front at install is introduced on its first return (Margin has no proof WebKit has seen it in a window); then a page that navigated in front (a link) in that tab: its return isn't introduced (the proof is kept through the link) |
| `bfcache` | A page back from the back/forward cache has its listeners on `browser.*` events again (they come off as a page is left): a change in storage reaches it |
| `reloaded` | Safari reloading Margin while pages are open (an update, or Margin.app opened): it keeps Margin's content-script world in those pages, still bound to the copy that's gone (the `uninstall` step's `keepWorld`). | `reloaded-newtab` | The same reload with Margin's new-tab page open: that page, at the old copy's address, answers nothing; it's loaded again at this copy's (`?again`, so ⌘T's hand-off doesn't close it) and shows every tab |
| `wake-wait`, `wake-cap`, `wake-awake` | A switch to a tab whose wake answers late (here a page busy from the moment the wake's hold reaches it: the host can't suspend a process; shown once first) keeps the page before on screen until it answers. 60 ms in, the tab is kicked (to the front and back in one turn) before its real show, then prepared and drawn before it's shown; with no answer by 1.6 s, a click goes on waiting while its page's deadline leaves room (here the answer at 2.2 s), then it's drawn and shown. The page before is hidden once (the switch), never by the kick. A tab that answers in time isn't kicked before 60 ms |
| `wake-reveal`, `wake-space` | The sidebar brought out wakes the tab used before the one in front, and a pointer resting on a space's icon wakes that space's most recent tab; the switch after takes the wake on, and the switch log says what started it (`reveal`, `space`) |
| `space-press`, `space-click` | A press on a space's icon shows that space in the sidebar at once and brings its tab to the front with the button still down; the release asks nothing more. Then back with a click from the page that came: the page left shows its own space's rows again at once, the same rows it drew before (not built anew), not the space it asked for before it went. `space-click` holds the button 100 ms, as a hand does, to time a build that switches on click; both log the press, the sidebar's change and the tab shown (Date.now) |
| `keep-ready-cap` | Keep-ready's holds through nine switches in the host's tab bar: the two tabs left last are held, the first seven let go at once (each hold counted in Margin's page as a message waiting for its answer, `content/hold.js`), and none is a script left running in the page's own world (`keepAwake`'s `pageswap` listener, counted there) |
| `keep-ready-away` | Safari left for another app (the page in front's `away`, sent from its Margin world: the host never has focus): the two tabs held are still held 3.5 s later (a page's word lets go after 15 s, past the host's background life: unit tests), and the same word from a tab behind doesn't count |
| `titles` | A hidden tab's title changing eight times in half a second: at most two writes of the open tabs (counted in the front page's Margin world), and its row ends on the last title; the tab in front's own title is written at once (all within the host's ~5 s of background life) |
| `addresses` | A hidden tab's new address (`pushState`) stored at once, and a new fragment alone a moment later (gathered with its title and icon) |
| `sleep-show`, `sleep-switch` | A tab put to sleep (background/sleep.js): sent to Margin's sleep page, its page's process exits (`pid`, `pidGone`), Margin keeps it as its page; woken by Safari's own show, or by Margin's switch (loaded behind the covered page, introduced, then shown), with one history entry and its content back |
| `sleep-kept`, `sleep-copy` | A tab with a typed draft and one on a site that never sleeps stay awake; a tab asleep when Margin is updated is moved to the new copy's sleep page, still asleep, and wakes when shown |
| `screenshot` | A page in its box, saved to `build/screenshot.png` to look at |

## Real websites

`open` also takes a full URL (`https://…`). The host logs every navigation (`nav <tab> top go <url>`, `committed`, `loaded`), so redirects and reload loops show. Each page's own console errors, warnings, uncaught errors and CSP violations are kept in `window.__pageLog` (read with a `page` step); Margin's log lines in the content-script world in `globalThis.__marginLog` (a `check`/`eval` step), since a site's CSP can block sending them to the server. Run a one-off scenario file with `./run.sh path/to/scenario.json`. Several runs can go at once with their own `MARGIN_HOST_PORT` and `MARGIN_HOST_BUILD` (a folder); `MARGIN_HOST_TIMEOUT` sets the time limit in seconds. The host has no signed-in accounts.

## Limits

- It isn't Safari. Everything around the engine is this program's: tabs, the window, sleeping tabs, launching and relaunching. That's where it can differ from Safari (it once loaded a hidden tab on `tabs.reload`, which Safari never does), so confirm tab and window behavior in Safari's own log (`/usr/bin/log show`, passively) or in Safari itself.
- Where it follows Safari on purpose (2026-10-29): `tabs.reload` leaves a tab asleep alone; a tab asleep is shown Safari's way, its web view into the window before it has a process and its load 30 ms later (Safari restores it after its session storage is back), so WebKit doesn't count that first moment in the window; selecting a tab takes 2 ms of the main thread (Safari's own selection turn lasts 2–74 ms in its log), so a second tab change sent with the first lands in the same run loop turn, as in Safari; the `deferLoads` step loads a tab asleep only if it's still the one shown once the turn is over (Safari can put a selected tab's load off until its selection update is done), and makes its web view as it's selected all the same, as Safari does (a script there then gets an error in place of a result, rather than failing). A web page's tab put to sleep (`sleep`, `restart`) loads again from its saved history (`WKWebView.interactionState`), as Safari restores one (`restoreFromSessionState`, then `goToBackForwardItem`, with no process yet, in Safari's log of 2026-11-02): its page's navigation is `back_forward`, as in Safari.
- Margin's background (a service worker) stops about 5 s after it starts, whatever the build, and nothing starts it again: every message after that gets an empty answer (`browser.runtime.sendMessage` resolves to undefined at once). Neither page messages nor tab events keep it running, and `loadBackgroundContent` takes it as still loaded. Safari keeps it running while it's needed and wakes it for a message. So a scenario does what needs the background within about 4 s of `install` (or splits into several scenarios); a step later than that fails, at random near the edge. On 2026-11-02, with the Mac busy (load average 7–20), it often stalled from about 1 s after it started, timers and all (a heartbeat every 100 ms in it stopped for 2–4 s), on this build and on HEAD's alike: `tabids` failed on both. A scenario whose switch lands well past that is flaky then. To check, send 30 × `getZoom` from a page and look for `undefined`.
- A tab's web view is made again when `tabs.update` takes it between a web page and an extension page, or from a copy's pages to another's (its configuration belongs to one), as Safari's tabs go anywhere. The new web view has a history of its own (what Safari does with a tab's history then isn't known). An extension page's web view the tab leaves is kept, out of the window: closing one stopped Margin's background for good here (2026-11-04). WebKit refuses a web page's own navigation to an extension page (−1008) and never commits an extension page's own navigation to a web page: both go through `tabs.update`. The host keeps its pages visible as Safari's on-screen window does: its web views ignore the window server's occlusion (macOS sometimes marks the off-screen window occluded, and a tab that was shown then stayed `document.hidden`), and App Nap is off for the run (an accessory app with only an off-screen window is napped after a minute or so).
- Memory: a page that navigates from a `page` step (the host's `callAsyncJavaScript`) stays in memory when any content-script world is in the page, even an empty one, so footprints measured that way grow with every navigation whatever Margin does. Let the page navigate itself (a link, its own script) to measure memory. `heap <pid>` and `vmmap --summary <pid>` work on the host's web content processes and count what's kept (`WebCore::HTMLDocument`, `WebKit::WebExtensionAPINamespace`: one per page kept).
- No real trackpad: the `pinch` step sends real magnify events, but how gestures feel, and pull-to-refresh, aren't covered here. Off-screen snapshots can't show whether text is sharp.
- The engine is the one in the installed macOS, which may be newer or older than a user's Safari.
